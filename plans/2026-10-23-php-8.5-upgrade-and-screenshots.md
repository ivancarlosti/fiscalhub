# PHP 8.5 runtime and real screenshots

- **Date:** 2026-10-23
- **Status:** Implemented
- **Scope:** `Dockerfile`, `.dockerignore`, `.github/workflows/build.yml`, `README.md`,
  `docs/screenshots/`, `plans/`

## Why

Fiscal Hub inherited its runtime from `php:8.3-fpm-alpine`. PHP 8.3 leaves
security support on 2026-12-31, roughly two months after this change, so every
deployment would soon run an unsupported branch. PHP 8.5 is the current stable
line and the official Alpine image is a drop-in replacement: the application
touches very little of the surface that changed in 8.4/8.5, and it has no
Composer dependencies to re-resolve.

The README also described the base image as `php:8.3-cli-alpine`, which was
never true — the container runs PHP-FPM behind nginx. Three places carried that
claim, the project tree still listed the pre-rename workflows
(`release_build.yml`, `update_readme.yml`) and there was no visual documentation
of the interface at all.

## PHP 8.5 compatibility

The application was audited against the deprecations and removals that landed
in PHP 8.4 and 8.5:

- no implicit nullable parameter declarations (`function f(Type $x = null)`);
- no `session.sid_length` / `session.sid_bits_per_character` ini overrides;
- no deprecated `(boolean)`/`(integer)`/`(double)`/`(binary)` casts, no
  `case ...;`, no backtick shell execution;
- no `utf8_encode()` / `utf8_decode()`, no `strftime()` / `gmstrftime()`;
- no `mysqli`-style syntax, no `__sleep()` / `__wakeup()` magic methods;
- `$_SESSION` access goes through `??` / `isset()`, never a null offset;
- no `$http_response_header`, `xml_parser_free()`, `socket_set_timeout()` or
  other PHP 8.5 deprecations;
- `ord()` only ever receives a single-byte string offset.

The one incompatibility found was `curl_close()`, which PHP 8.5 deprecates
because it has had no effect since PHP 8.0. All seven calls were removed. This
was not cosmetic: with `display_errors` on, the deprecation notice printed
before the proxy headers, the response became `text/html` and the CNPJ tab
reported `Unexpected token '<', "<br />..." is not valid JSON`. Under the default
production configuration the JSON still parsed, but every request would have
written a deprecation to the error log.

The only dependency is the official image, so there is no lock file to bump.
`php -l` passes on all nine `webapp/*.php` files — the repository has no
`composer.json` or PHPUnit suite, so validation is the image build plus HTTP
smoke tests.

## Screenshots

`docs/screenshots/generate.sh` builds `fiscalhub:screenshots`, starts three
containers from it and captures:

| File | Origin | Screen |
| --- | --- | --- |
| `01-upload-xml-light.png` | `AUTH_METHOD=none` | Upload de XML, light |
| `02-consulta-chave.png` | `AUTH_METHOD=none` | Consulta por chave, 44 digits filled |
| `03-consulta-nfe.png` | `AUTH_METHOD=none` | Consulta NF-e directory |
| `04-consulta-cnpj.png` | `AUTH_METHOD=none` | Consulta CNPJ (BrasilAPI, public record) |
| `05-upload-xml-dark.png` | `AUTH_METHOD=none` | Upload de XML, dark |
| `06-login-account.png` | `AUTH_METHOD=account` | Credential form |
| `07-login-keycloak.png` | `AUTH_METHOD=keycloak` | SSO gate |
| `08-mobile.png` | `AUTH_METHOD=none` | Upload de XML at 390x844 |

The driver uses headless Chrome over the DevTools Protocol, so no npm package
is installed and nothing is added to `package.json`. PNGs are written at
1440x900 (390x844 for mobile) with a device pixel ratio of 2 and full-page
height capped at 2400 CSS pixels, then reduced to a 256-colour palette when
Pillow is available. The keycloak container points at
`https://keycloak.invalid`; only the login gate is rendered, no provider is
contacted. The account credential exists inside the throwaway container and is
never committed.

Capturing the mobile screen at 390px exposed a real defect: the header needed
about 436px, so the third language flag was clipped. The `≤525px` media query
now reduces the header gap, the theme/logout buttons and the flags, which keeps
every control inside a 390px viewport.

## Verification

The image was built and exercised on the host (PHP 8.5.12, Chrome 156, Docker
29.9):

```sh
docker build -t fiscalhub:php85 .          # 154 MB, PHP 8.5.12
for f in webapp/*.php; do php -l "$f"; done # 9 files, no syntax errors
docker run ... php -m | grep -ix curl       # curl
```

An `E_ALL` ini file was mounted into three containers (`AUTH_METHOD` = `none`,
`account`, `keycloak`) and every public endpoint was requested:

| Check | Result |
| --- | --- |
| `GET /` (`none`) | 200 |
| `POST /brasilapi-proxy.php` (CNPJ 33.000.167/0001-01) | 200, `application/json`, Petrobras payload |
| `POST /login.php` (account, valid) | 302, then `GET /` with the session cookie → 200 |
| `POST /login.php` (account, wrong password) | 302 → `login.html?error=invalid` |
| `GET /keycloak-login.php` | 302 to `https://keycloak.invalid/realms/.../auth` with PKCE + state |
| Container logs | no `Deprecated`, `Warning`, `Fatal` or `Uncaught` lines |

`docs/screenshots/generate.sh` exited 0 and produced the eight files listed
above, 590 KiB in total after palette reduction. Every local image referenced
by `README.md` exists.

## Rollback

- Revert the first line of `Dockerfile` to `FROM php:8.3-fpm-alpine` and
  rebuild. Nothing else depends on 8.5: the `curl_close()` removals are no-ops
  on 8.0–8.4, and the CSS tweak is version-independent.
- To stay on 8.5 while pinning a known-good build, use
  `FROM php:8.5.12-fpm-alpine` (or its digest).
- The screenshots, `docs/`, `plans/` and the README gallery are additive; they
  can be dropped without affecting the runtime. The `.dockerignore` and ZIP
  exclusions only need to be reverted if those directories go away.
